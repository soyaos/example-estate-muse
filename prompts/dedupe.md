# dedupe — 第 3 步：只选择候选编号，不再重写表格

用户消息JSON的original_request是原始需求，previous_stage_output是程序整理的候选JSON。
target_count是必须选择的数量（当前EstateMuse为500）。
保留原始预算、客群、城市、平台、新房/二手房范围、获客目标及事实限制。
读取previous_stage_output中的rows数组，按数组顺序编号：第一行为1，第二行为2，依此类推。

## 选择
先逐行审查，不得直接返回前500个编号。标题必须为问题，钩子必须有“拍摄前需核实：”；
排除擅自下市场结论、保证增值、冒称实测/经历、危险测试、卖家营销或无关家务的候选。
问号不能消除标题里的事实预设：排除无来源的具体层高、政策已执行、某类房源必然更好等前提；“新房某属性好vs二手某属性差”也必须排除。
相近题目只换“新房/二手房/杭州”或少量词语却回答同一问题，也按语义重复排除。
在合格前提下尽量每个维度保留约60条，不按数组末尾裁掉compare维度；质量优先于配比。
1. 只从已有候选中选择target_count个不同编号，不生成任何新选题。
2. 优先选择符合原始业务的不同问题和拍摄动作，排除语义重复、无关内容和标题党。
3. 同时销售新房和二手房时两类与对比均覆盖；指定视频时优先选可拍摄内容。
4. 未提供可核实来源时，不编造事实，也不要选择宣称真实成交、确定性价格、
   客户经历、涨跌、收益或政策结论的候选；数据类只能选标明“需核实”的待研究问题。
5. 尽量覆盖八个维度；不为了配比例选不真实或不符需求的候选。
6. 如果合格候选不足，不得选择坏行凑数：返回实际可选编号。程序会拒绝不足，
   不能谎称完成500条。候选生成补齐由程序负责，不由本阶段重写。

## 修复
repair=true表示上一份编号结果未通过验证，validation_error说明原因。
重新给出完整的编号列表，遵守整数、范围、唯一性与target_count要求。
不要附带旧的无效列表或解释，不通过伪造新行解决数量问题。

## 输出
只输出 {"indices":[1,2,3]} 形状的JSON对象。
示例只说明格式；正常实际列表必须有target_count个不同的一基整数。
不得包含小数、负数、零、越界编号、重复编号、范围简写或省略符。
不输出rows、columns、标题、钩子或工作簿JSON；程序按编号原样选取已有行并组装Excel。
